## 1. 引言

### 1.1 目的

本文档是对《JARVIS 功能需求补充清单》中 13 条补充需求的展开细化，将每条需求从一句话扩展为具备明确功能边界、子功能拆解、交互流程、异常处理与验收标准的可执行规格，供产品、研发、测试及后续维护人员使用。

### 1.2 范围

本文档覆盖以下能力域：虚拟机管理、镜像导入、本地模型私有化部署、功能可用性原则、权限体系、多平台支持、语音（声线与唤醒）、长期记忆、云端互联、模型能力调度。

### 1.3 术语与定义

| 术语 | 定义 |
| --- | --- |
| JARVIS | 本文档所指的智能助手系统（主体产品）。 |
| 虚拟机（VM） | 由虚拟机监控程序（Hypervisor）创建的隔离计算环境，包含虚拟 CPU、内存、磁盘与网络设备。 |
| 镜像（Image） | 虚拟机或系统的磁盘映像文件，可包含完整的操作系统与预装环境。 |
| Hypervisor | 虚拟机监控层，如 QEMU/KVM、VirtualBox、VMware、Apple Virtualization Framework 等。 |
| 本地模型 | 部署在用户本机、由本地推理引擎运行的大语言模型或其他 AI 模型。 |
| 模型格式 | 模型的序列化存储格式，如 GGUF、ONNX、Safetensors、PyTorch、TensorFlow、CoreML 等。 |
| 声线 | 语音合成（TTS）所使用的声音音色，可包含多个音色包。 |
| 唤醒识别 | 持续监听音频流，判断是否出现针对 JARVIS 的呼唤（唤醒词或定向呼叫）。 |
| 记忆文件 | 用于持久化存储对话与关键信息的本地文件。 |
| 能力画像 | 对每个模型在代码、数学、写作、推理等能力域的强项/短板标注。 |
| 接口 | 真实可用的功能入口（含协议、参数与适配层），接入对应设备即可直接使用，非功能占位符。 |

### 1.4 总体原则

1. **可交付优先**：所有列入本规格书的功能必须真实实现并可通过验收，不以"预留接口"代替功能实现。
2. **用户可控**：涉及权限、隐私、资源消耗的功能，均提供明确的用户授权与开关控制。
3. **本地优先**：对话记忆、模型推理、唤醒识别等涉及隐私的核心能力默认在本地完成。
4. **扩展友好**：虚拟机后端、模型引擎、声线来源、云端通道均采用插件化设计，便于接入新实现。

## 3. 详细需求规格

### 3.1 需求 1：虚拟机操作能力（REQ-01）

**原始需求**：JARVIS 要可以操作虚拟机。

**优先级**：P0

#### 3.1.1 需求描述

JARVIS 应具备对虚拟机的完整操作能力，覆盖虚拟机从创建到销毁的全生命周期，并能在虚拟机内部执行命令、读写文件、安装与管理软件，操作结果实时反馈给用户。

#### 3.1.2 子功能拆解

| 编号 | 子功能 | 详细说明 |
| --- | --- | --- |
| REQ-01-S1 | 虚拟机生命周期管理 | 创建、启动、暂停、恢复、重启、关机、销毁虚拟机；支持开机自启配置。 |
| REQ-01-S2 | 虚拟机内部操作 | 在虚拟机内执行 Shell 命令、读写文件、上传/下载文件、安装与卸载软件包、管理服务（systemd 等）。 |
| REQ-01-S3 | 快照管理 | 创建快照、回滚快照、删除快照、列出快照；支持对快照命名与备注。 |
| REQ-01-S4 | 资源配置管理 | 查看与调整虚拟 CPU 核数、内存大小、磁盘容量、网络模式（NAT/桥接/仅主机）。 |
| REQ-01-S5 | 资源监控 | 实时查看虚拟机 CPU、内存、磁盘、网络使用率，并支持阈值告警。 |
| REQ-01-S6 | 网络管理 | 查看虚拟机 IP、配置端口映射、管理虚拟网络。 |
| REQ-01-S7 | 日志与状态查询 | 查看虚拟机运行状态、开机日志、错误日志。 |

#### 3.1.3 操作方式与权限

- JARVIS 通过 Hypervisor 适配层（如 libvirt/QEMU、VirtualBox CLI 等）执行操作，禁止直接操作宿主物理资源。
- 所有虚拟机操作需在用户授权范围内执行；首次操作需用户确认，可配置"仅提示一次"或"始终授权"。
- JARVIS 执行虚拟机内命令时，以虚拟机内指定用户身份登录执行（默认见 REQ-07）。

#### 3.1.4 交互流程（示例：创建并进入虚拟机）

1. 用户发出指令"帮我创建一台 Ubuntu 虚拟机并进入终端"。
2. JARVIS 确认需求（系统、版本、资源配置），如信息不足则向用户询问或采用默认配置。
3. 调用虚拟机管理模块创建虚拟机并启动。
4. 等待系统就绪后，通过 SSH 或 QEMU Guest Agent 建立会话。
5. 执行用户要求的命令并回显结果；会话保持可连续操作。
6. 操作完成后输出虚拟机概要信息（IP、配置、运行状态）。

#### 3.1.5 边界与异常

| 场景 | 处理方式 |
| --- | --- |
| Hypervisor 未安装/不可用 | 提示用户缺失组件并提供一键安装引导。 |
| 虚拟机内部命令无响应 | 超时后返回部分输出，提示会话可能已断开，提供重连动作。 |
| 宿主资源不足 | 创建前检查资源，资源不足时明确提示并建议最小配置。 |
| 用户取消授权 | 终止操作并记录审计日志。 |

#### 3.1.6 验收标准

- 能通过自然语言完成虚拟机创建、启动、命令执行、快照、暂停、恢复、销毁全流程。
- 命令执行结果正确回显，失败场景有明确错误信息。
- 全部操作留痕于审计日志。

### 3.2 需求 2：虚拟机系统版本选择列表（REQ-02）

**原始需求**：虚拟机安装提供列表给用户选择版本，支持 Kali Linux。

**优先级**：P0

#### 3.2.1 需求描述

JARVIS 提供"可安装系统版本列表"，用户可在界面或对话中浏览并选择操作系统及其具体版本进行安装。**Kali Linux 为首发必须支持项**，同时提供主流 Linux 发行版与常用系统。

#### 3.2.2 系统与版本列表（首发范围）

| 系统 | 首发支持版本 | 说明 |
| --- | --- | --- |
| Kali Linux | 最新稳定版及上一稳定版 | 首发必选；含滚动更新版本选项 |
| Ubuntu | LTS 最新两版 | 可选 |
| Debian | 最新稳定版 | 可选 |
| CentOS Stream / Rocky Linux | 最新稳定版 | 可选 |
| Windows | 受支持的评估版/正式版（如用户提供镜像） | 列表展示，安装依赖用户镜像（REQ-03） |

> 注：版本号以官方发布为准，安装时动态拉取官方源元数据，避免写死过期版本号。

#### 3.2.3 列表信息字段

每条列表项至少包含：系统名称、版本号、架构（x86_64/ARM64）、镜像来源、预计下载大小、推荐配置（CPU/内存/磁盘）、系统类型标签（如"安全测试""服务器""桌面"）。

#### 3.2.4 安装流程

1. 用户选择系统与版本（或直接说"装一个 Kali"）。
2. JARVIS 展示该版本的配置建议，确认后开始下载官方镜像。
3. 下载完成后校验镜像完整性（SHA-256）。
4. 创建虚拟机并完成无人值守安装/导入。
5. 安装完成进行初始化（设置默认账户、网络、SSH/Guest Agent），向用户报告结果。

#### 3.2.5 边界与异常

| 场景 | 处理方式 |
| --- | --- |
| 镜像源不可达 | 提供备用镜像源切换，或引导用户通过 REQ-03 手动导入镜像。 |
| 下载中断 | 支持断点续传，失败可重试。 |
| 用户选择列表外系统 | 引导使用镜像导入能力（REQ-03）。 |
| 磁盘空间不足 | 安装前检查并提示所需空间。 |

#### 3.2.6 验收标准

- 界面与对话两种方式均可浏览并选择列表内系统及版本。
- 选择 Kali Linux 后可自动完成安装并进入可用状态。
- 列表信息（版本、大小、推荐配置）与官方源一致，且可刷新更新。

### 3.3 需求 3：用户导入虚拟机镜像（REQ-03）

**原始需求**：用户自己可以导入虚拟机镜像。

**优先级**：P0

#### 3.3.1 需求描述

支持用户导入自有虚拟机镜像文件，导入后镜像注册为可启动虚拟机，与预装系统一样可被 JARVIS 操作。

#### 3.3.2 支持的镜像格式（首发）

| 格式 | 说明 |
| --- | --- |
| OVA / OVF | 打包的虚拟机模板（含虚拟机配置） |
| QCOW2 / QCOW | QEMU 磁盘映像 |
| VMDK | VMware 磁盘映像 |
| VHD / VHDX | 微软虚拟磁盘格式 |
| RAW | 原始磁盘映像 |
| ISO | 安装镜像（导入后作为安装源，引导创建虚拟机） |

#### 3.3.3 导入流程

1. 用户提供本地镜像文件路径，或通过文件选择器/拖拽上传。
2. JARVIS 识别镜像格式与元信息（系统类型、磁盘大小、引导方式）。
3. 执行完整性校验与安全检查（见 3.3.4）。
4. 将镜像注册到虚拟机库，生成默认配置（可按需调整）。
5. 创建并启动虚拟机，初始化连接（设置账户、网络、Guest Agent）。
6. 向用户返回导入结果与虚拟机概要。

#### 3.3.4 安全与边界

- 导入前进行格式与元数据校验，拒绝损坏或非法文件，并给出原因。
- 镜像来源不可信时，提示用户确认来源；不主动执行镜像内未知脚本。
- 超大镜像（超过用户设定阈值）提示预计耗时与所需磁盘空间，由用户确认后继续。
- 不支持加密镜像与专有封闭格式（如未解包的 Apple DMG），给出明确提示。

#### 3.3.5 验收标准

- 至少支持 OVA/OVF、QCOW2、VMDK、VHD/VHDX、RAW、ISO 六类格式的导入。
- 导入成功后虚拟机可启动，并可由 JARVIS 正常操作。
- 损坏文件、空间不足、格式不支持等异常均给出明确中文提示，不产生静默失败。

### 3.4 需求 4：本地模型导入与私有化部署（REQ-04）

**原始需求**：用户也可以自己导入本地模型进行私人本地部署，支持所有格式的模型。

**优先级**：P0

#### 3.4.1 需求描述

支持用户导入本地 AI 模型文件并在本机完成私有化部署，部署后的模型可被 JARVIS 作为对话/任务执行引擎调用。**"支持所有格式"按下列清单覆盖主流格式，并保持格式扩展能力**（技术上不存在真正"所有格式"统一运行时，规格上承诺全量覆盖主流开放格式，并动态适配新格式）。

#### 3.4.2 支持格式与对应引擎（首发）

| 模型格式 | 典型后缀 | 运行引擎 |
| --- | --- | --- |
| GGUF | .gguf | llama.cpp / Ollama |
| ONNX | .onnx | ONNX Runtime |
| Safetensors | .safetensors | Transformers / vLLM |
| PyTorch | .bin / .pt / .pth | Transformers / vLLM |
| TensorFlow | .pb / SavedModel | TensorFlow Serving / Transformers |
| CoreML | .mlpackage / .mlmodel | CoreML（Apple 平台） |
| 其他量化/混合格式 | 由插件识别 | 动态适配 |

#### 3.4.3 导入与部署流程

1. 用户提供模型文件或模型目录（含配置文件），或指定本地路径。
2. JARVIS 自动识别模型格式、架构、参数量、量化等级与依赖配置。
3. 检测本机资源（GPU 显存、内存、磁盘），给出部署可行性评估与推荐参数。
4. 选择合适的推理引擎并完成部署（必要时自动转换/量化，保留原文件）。
5. 进行连通性测试（加载模型、发起一次推理请求）。
6. 将模型注册到模型库，可设为默认模型；向用户报告部署结果与资源占用。

#### 3.4.4 模型库与运行管理

- 支持多模型并存，可查看模型列表、切换默认模型、停止/启动模型服务。
- 模型服务按需加载（空闲释放），支持常驻模式配置。
- 提供本地推理接口，供 JARVIS 对话与 REQ-13 模型调度调用。

#### 3.4.5 边界与异常

| 场景 | 处理方式 |
| --- | --- |
| 硬件资源不足 | 明确提示最低与推荐配置，提供量化/降级建议，不强行部署。 |
| 模型文件损坏/缺依赖 | 定位缺失文件或依赖，给出修复指引。 |
| 格式无法识别 | 提示支持格式清单与转换建议（如转 GGUF）。 |
| 多模型竞争显存 | 按用户配置的优先级调度，防止 OOM 崩溃。 |

#### 3.4.6 验收标准

- 至少完成 GGUF、ONNX、Safetensors、PyTorch 四类格式的端到端部署（导入→加载→推理成功）。
- 资源不足、格式不支持等场景均给出明确提示。
- 部署后的模型可被对话调用，并可参与 REQ-13 的能力调度。

### 3.5 需求 5：功能可用性原则——接口即插即用（REQ-05）

**原始需求**：所有功能能实现的就实现，留下接口的意思是接上对应设备就可以直接使用，而不是留一个功能占位符。

**优先级**：P0（全局约束，适用于所有需求）

#### 3.5.1 原则定义

1. **能实现即实现**：凡本规格书列入的功能，必须交付真实可用实现，不得仅提供"预留接口/待开发"占位。
2. **接口 = 真实功能入口**：所谓"接口"指已实现功能的对适配层——接上对应设备、驱动或服务后即可直接使用，例如插入麦克风即可用语音、接入蓝牙音箱即可播放、接入外部 GPU 即可加速推理。
3. **禁止占位符**：产品中不得出现"功能即将上线""预留 X 接口（暂无实现）"等占位形态。

#### 3.5.2 接口管理规范

- 每个对外接口必须有：接口定义（协议/参数/返回值）、真实实现、自动化测试、使用文档。
- 依赖外部硬件/服务的功能（如外接设备），在设备未接入时明确提示"未检测到设备"，而非假装可用；设备接入后无需二次开发即可使用。
- 新增能力必须经过"实现→联调→测试→上架"完整链路后方可对外暴露。

#### 3.5.3 验收标准

- 逐项核对本文档全部需求，不存在未实现的占位接口。
- 抽查任意声明的接口：接入对应设备后即可调用且功能符合描述。
- 设备缺失场景提示清晰，且不影响其他功能使用。

### 3.6 需求 6：虚拟机 Root 权限支持（REQ-06）

**原始需求**：虚拟机支持 root 权限。

**优先级**：P0

#### 3.6.1 需求描述

JARVIS 创建的虚拟机（以 Linux 系为主）默认支持 root 权限使用，用户与 JARVIS 均可通过 root 身份执行特权操作。

#### 3.6.2 规格要求

- 系统安装完成后默认启用 root 账户（设置强密码并提示用户修改），或提供 sudo 免密/授权通道，保证特权操作可用。
- JARVIS 执行虚拟机内特权操作时，可通过已配置的 root 凭据或 sudo 机制完成（凭据加密存储于本地凭据库）。
- 提供"是否允许 JARVIS 使用 root 权限"的独立开关；关闭后 JARVIS 仅以普通用户身份操作。
- root 操作（执行命令、安装软件、修改系统文件、删除文件等）记录审计日志。

#### 3.6.3 安全要求

- root 凭据不得明文存储，不随日志、对话记录输出。
- 涉及 root 的危险操作（格式化、删除关键目录、关闭防火墙等）执行前二次确认。
- 支持用户一键重置虚拟机 root 密码。

#### 3.6.4 验收标准

- 新装 Linux 虚拟机可执行 `sudo` 及 root 登录操作。
- JARVIS 可在授权下以 root 身份安装软件、修改配置并成功返回结果。
- 未授权时 root 操作被拒绝并提示；危险操作有确认环节。

### 3.7 需求 7：JARVIS 以高级用户身份使用虚拟机（REQ-07）

**原始需求**：JARVIS 可以高级用户的身份使用虚拟机。

**优先级**：P0

#### 3.7.1 需求描述

JARVIS 进入虚拟机执行任务时，以"高级用户（超级用户/特权用户）"身份运行，具备完整系统操作能力（安装软件、修改配置、管理系统服务、部署环境等），而非仅普通用户权限。

#### 3.7.2 身份与权限模型

| 项目 | 说明 |
| --- | --- |
| 默认身份 | 虚拟机内 root 或拥有 sudo 全权的管理员账户（由 REQ-06 保证） |
| 会话建立 | JARVIS 通过 SSH / Guest Agent 以高级身份建立会话，支持密钥认证 |
| 权限范围 | 系统内任意文件与命令（受虚拟机自身边界约束） |
| 用户控制 | 全局开关"允许 JARVIS 使用高级权限"，默认开启、可随时关闭；可配置为"每次询问" |

#### 3.7.3 与普通用户身份的区别

- 普通用户会话：只读查询、用户级操作（个人文件、普通命令）。
- 高级用户会话：系统级操作（软件安装、服务管理、系统配置、跨用户文件）。
- JARVIS 根据任务复杂度自动选择身份；明确需要特权时提示用户并切换，切换过程可见可查。

#### 3.7.4 验收标准

- JARVIS 能在高级身份下完成系统级任务（如安装 Nginx、创建系统服务、修改系统配置）并验证生效。
- 特权操作有审计记录；开关关闭后自动降级为普通用户并给出提示。

### 3.9 需求 9：默认声线联网下载（REQ-09）

**原始需求**：默认声线上网查找并下载。

**优先级**：P1

#### 3.9.1 需求描述

首次启用语音功能时，JARVIS 通过联网从官方声线库/授权渠道检索并下载默认声线（TTS 音色）到本地，下载完成后作为默认语音音色使用。

#### 3.9.2 功能规格

- **首次引导**：语音能力首次启用时，自动联网获取默认声线；展示声线名称、大小、来源与下载进度。
- **声线检索**：支持从声线库按名称/风格/语言检索并试听；提供多套默认声线候选。
- **下载与校验**：断点续传；下载后校验完整性（校验和）与授权有效性。
- **本地管理**：已下载声线本地缓存，支持切换、删除、恢复默认；离线时可使用内置最小声线降级，不阻断对话。
- **自动更新**：声线库有新版本时提示更新（用户可选择是否自动更新）。

#### 3.9.3 边界与异常

| 场景 | 处理方式 |
| --- | --- |
| 无网络/源不可达 | 使用内置最小声线，提示联网后自动补下载；不反复打扰。 |
| 下载失败/损坏 | 自动重试两次后报告原因，提供手动重试入口。 |
| 声线授权过期 | 提示重新获取授权，不影响文字对话。 |

#### 3.9.4 验收标准

- 首次启用可完成默认声线"检索→下载→校验→启用"全流程。
- 断网时语音功能有可用的降级声线；恢复联网后可补下并自动切换。

### 3.10 需求 10：语音呼唤自我识别（REQ-10）

**原始需求**：语音呼唤时，会自动识别是否在呼唤自己。

**优先级**：P1

#### 3.10.1 需求描述

JARVIS 持续监听语音输入，自动判断语音是否在呼唤 JARVIS 本机（唤醒词/名称呼唤/定向呼叫），识别成功后才进入响应，避免误唤醒与误响应。

#### 3.10.2 功能规格

- **唤醒词识别**：默认唤醒词为"JARVIS"（可自定义），支持多词/中英文唤醒词配置。
- **定向呼唤识别**：对"JARVIS，帮我……""嘿 JARVIS"等呼唤句式进行识别判定。
- **误唤醒抑制**：结合说话人定向、音频能量、关键词置信度与上下文过滤，降低电视/他人对话导致的误唤醒。
- **灵敏度调节**：提供"高/中/低"灵敏度档位与自定义阈值。
- **隐私处理**：唤醒检测默认本地完成，不将持续音频上传云端；仅唤醒成功后的指令按需处理。
- **状态反馈**：唤醒成功后通过提示音/指示灯反馈，明确"正在聆听"。

#### 3.10.3 边界与异常

| 场景 | 处理方式 |
| --- | --- |
| 连续误唤醒 | 提示用户调整灵敏度或更换唤醒词。 |
| 麦克风占用/权限缺失 | 明确提示并引导开启权限。 |
| 多设备同处一室 | 支持按设备名定向应答，避免多端同时响应（与 REQ-12 协同）。 |

#### 3.10.4 验收标准

- 发出唤醒词后正确进入响应；无关对话不触发（在规定误唤醒率内）。
- 唤醒词可自定义并即时生效；灵敏度可调。
- 唤醒识别过程本地完成，无持续音频外传。

### 3.11 需求 11：本地长期记忆系统（REQ-11）

**原始需求**：从启用开始一直记录每一次对话记忆，存入记忆文件，存放于本地，为 AI 提供长期记忆。

**优先级**：P0

#### 3.11.1 需求描述

从 JARVIS 首次启用起，持续记录每一次对话，形成长期记忆并持久化到本地记忆文件中，使 JARVIS 在后续对话中可检索、引用历史信息，提供连续的个性化体验。

#### 3.11.2 记忆内容与结构

| 类别 | 内容 | 示例 |
| --- | --- | --- |
| 对话记录 | 每次对话的完整原文与时间戳 | 2026-10-09 对话全文 |
| 关键事实 | 用户身份、偏好、常用环境、决策 | 用户使用 Kali 做渗透测试学习 |
| 偏好记忆 | 反复出现的偏好与习惯（语气、工具、配置） | 默认用中文回复 |
| 任务轨迹 | 已完成任务的摘要与产物位置 | 曾创建 Ubuntu 虚拟机 |
| 用户画像 | 长期稳定的个人信息（经用户确认后写入） | 职业、技术栈 |

#### 3.11.3 存储设计

- **存储位置**：本地磁盘指定目录（默认 `~/.jarvis/memory/`，可配置）。
- **文件格式**：主存储采用 SQLite（结构化、支持检索）＋ 原文采用 JSONL 分日归档（可读、可备份）；记忆文件为 UTF-8 编码。
- **写入策略**：每次对话结束即增量写入；关键事实即时提取写入。
- **去重与更新**：相同事实以最新为准；过期/错误记忆支持用户删除或修正。
- **检索接口**：对话时按语义与关键词检索相关记忆，注入上下文；支持"记忆模糊"（相似度阈值）与时间范围过滤。
- **规模控制**：原文日志支持自动归档/压缩；结构化记忆设置容量上限与整理机制（合并相似条目）。

#### 3.11.4 隐私与安全

- 记忆默认仅存本地，不出本机；是否同步云端由 REQ-12 的授权开关决定。
- 提供记忆查看、导出、删除（单条/全部）能力。
- 可选开启本地加密（如 SQLCipher），密钥本地保管。
- 涉及敏感信息（密码、密钥、凭据）默认不写入记忆原文，如写入需用户确认。

#### 3.11.5 边界与异常

| 场景 | 处理方式 |
| --- | --- |
| 记忆文件损坏 | 自动备份恢复最近可用版本，并提示用户。 |
| 磁盘空间不足 | 触发归档与压缩，提示用户清理。 |
| 用户要求"忘记" | 支持按对话/按主题/全部清除，清除后不可恢复（二次确认）。 |

#### 3.11.6 验收标准

- 启用后所有对话均被记录；重启后 JARVIS 能引用此前对话中的关键信息。
- 记忆可查看、导出、删除；存储目录与格式符合本文档规定。
- 用户明确删除的记忆不再出现在后续对话上下文中。

### 3.13 需求 13：模型能力短板自动调度（REQ-13）

**原始需求**：用户选择了模型后，该模型如果存在功能短板或缺陷，在用户提出对应的要求时，立刻调用其他在这方面是强项的模型来辅助解决用户的要求。

**优先级**：P1

#### 3.13.1 需求描述

系统维护各模型的能力画像（强项/短板/缺陷）。当用户选择某一模型作为主模型后，若当前请求命中主模型的短板能力域，系统**立即自动调度**该能力域的强项模型协助完成，并将结果整合后返回用户，无需用户手动切换。

#### 3.13.2 能力域划分（首发）

| 能力域 | 说明 | 示例 |
| --- | --- | --- |
| 代码 | 编程、调试、代码解释 | 写脚本、修 Bug |
| 数学与逻辑 | 数值计算、推理证明 | 数学题、逻辑推导 |
| 中文写作 | 文案、公文、润色 | 写方案、改稿 |
| 多语言翻译 | 跨语言翻译 | 中英互译 |
| 专业知识 | 医学、法律、金融等垂直领域 | 术语解释、政策解读 |
| 图像/多模态 | 图像理解、OCR | 看图、识别表格 |
| 长文本处理 | 长文档摘要、长上下文 | 论文总结 |

#### 3.13.3 能力画像与注册

- 每款模型（含本地模型与云端模型）入库时生成/更新能力画像：按能力域标注"强/中/弱/缺陷"及适用说明。
- 画像来源：模型发布信息、评测数据、实测记录（本地模型部署后自动小样本实测），支持人工修正。
- 画像随模型更新而刷新；允许用户自定义某模型的画像。

#### 3.13.4 调度流程

1. 用户选择主模型 M（本地或云端均可）。
2. 用户提出请求 R。
3. 调度器判断 R 所属能力域及 M 在该域的表现：
   - M 为强项 → 由 M 直接完成；
   - M 为短板/缺陷 → 进入辅助调度。
4. 辅助调度：从可用模型中选择该能力域最强模型 N（优先本地，其次云端；用户可配置允许调用的模型池）。
5. 由 N 生成该部分结果，必要时 M 与 N 协作（M 提供上下文，N 产出结果）。
6. 结果整合：向用户说明"该请求由模型 N 协助完成（因主模型 M 在此方面较弱）"，保证透明。
7. 调度全程可追踪：用户可查看"本次使用了哪些模型"。

#### 3.13.5 用户控制

- 总开关"模型能力自动调度"，默认开启，可关闭（关闭后仅用主模型，短板时提示建议）。
- 可设置允许参与调度的模型白名单；可设置调度触发方式（自动/每次询问）。
- 本地模型调度不产生外部费用；云端模型调用前提示可能产生的额度消耗。

#### 3.13.6 边界与异常

| 场景 | 处理方式 |
| --- | --- |
| 无可用辅助模型 | 明确提示主模型短板，建议用户导入/配置强项模型（引导 REQ-04）。 |
| 辅助模型失败 | 回退主模型尝试，并如实报告。 |
| 用户关闭调度 | 保持主模型直接应答，必要时给出"可尝试启用辅助模型"建议。 |

#### 3.13.7 验收标准

- 构造"主模型在 X 域为弱项"的场景：用户提出 X 域请求时，系统自动调用 X 域强项模型并返回可用结果。
- 调度行为对用户透明（有明确说明与记录）；开关与白名单设置即时生效。
- 调度失败有回退与提示，不产生静默失败。

## 4. 非功能需求

### 4.1 性能

| 项目 | 要求 |
| --- | --- |
| 虚拟机操作响应 | 常规操作（状态查询、快照、启停）在 3 秒内给出结果反馈 |
| 命令执行回显 | 流式回显，首屏输出不超过 2 秒 |
| 模型加载 | 本地模型按需加载，加载过程有进度提示 |
| 唤醒响应 | 唤醒识别到响应启动不超过 1.5 秒 |
| 记忆检索 | 单次记忆检索注入上下文不超过 1 秒 |

### 4.2 安全

- 凭据（root 密码、模型 API Key、云端令牌）加密存储，禁止明文落盘与日志输出。
- 危险操作（删除、格式化、权限提升、批量数据操作）二次确认并审计。
- 所有外部通道（云端接口、模型 API）默认 TLS；支持本地纯离线运行。
- 记忆与对话数据默认本地存储，外传遵循用户授权。

### 4.3 兼容性

- 宿主平台：Windows / macOS / Linux 三端首发至少支持两类；虚拟机与语音能力按平台分级适配。
- 虚拟机后端：支持至少两种 Hypervisor 适配（QEMU/KVM 与 VirtualBox），可插拔扩展。
- 模型引擎：支持 Ollama、llama.cpp、ONNX Runtime、Transformers 等主流引擎插件化接入。

### 4.4 可用性

- 所有功能提供中文界面与中文错误提示。
- 功能降级（如断网、无 GPU、设备缺失）必须显式告知用户，不静默失效。
- 支持一键恢复默认配置；记忆与配置提供导出备份能力。

### 4.5 隐私

- 持续音频仅用于唤醒检测且本地处理；原始音频默认不保存（用户可开启保存并明确告知）。
- 记忆文件本地化存储；云端同步需逐项授权；用户可随时清除全部本地数据。

## 6. 验收总则

1. **逐条验收**：以本文档 3.1～3.13 各节的"验收标准"为唯一依据，逐条核销，未通过项不得进入发布。
2. **无占位验收（REQ-05）**：发布前执行全功能清单核查，确认不存在占位接口。
3. **回退验证**：对异常路径（断网、资源不足、权限拒绝、设备缺失）逐项实测。
4. **数据验证**：记忆、日志、审计数据可导出核验，删除操作可追踪。
5. **版本留档**：每次发布保留需求—实现—测试的对应记录。
