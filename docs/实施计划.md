## 0. 设计方向与工作目标

### 0.1 产品定位

JARVIS 是 Android 端智能 AI 助手（包名 `com.jarvis.pineapple`，版本 0.0.1），人格为《钢铁侠》中文版 JARVIS。第一版只交付 Android 侧载 APK。本地优先：用户自有模型 > LiteRT 本地模型 > API 模型 > 个人服务器模型。

### 0.2 工作目标

把现有代码从「骨架 + 部分真实实现 + 历史占位」推进到：

1. 规格书第五章全部非预留项可从 UI 或对话链路真实触达。
2. 补充规格 REQ-01～REQ-13 按优先级闭环（能实现则实现，缺硬件/云端时明确提示「未检测到」，禁止假成功）。
3. 单元测试与集成测试全部通过。
4. 产出 Debug APK，交给用户实机审查。
5. 实机通过前不打包 Release。

### 0.3 完成总标准（Definition of Done）

| 项 | 判定 |
|----|------|
| 追踪矩阵 | `docs/requirements_traceability.md` 无 `MISSING`；`PARTIAL` 仅允许「缺硬件/未配置云」且有明确用户提示 |
| 测试 | `./gradlew testDebugUnitTest` 全部通过 |
| 构建 | `./gradlew assembleDebug` EXIT=0 |
| 占位 | 禁止空 `onClick`、假进度条、硬编码成功、写死假数据冒充完成 |
| 预留项 | 科幻/违法/无硬件项仅保留接口 + 明确「未检测到设备/不受支持」 |
| 推送 | 每阶段提交已在 `origin/main` |
| Release | 用户实机清单全部勾选后才允许 |

## 2. 执行纪律（每一步都遵守）

1. **只做当前阶段任务**，不顺手改无关模块。
2. **先改代码，再跑测试**。测试失败则修到通过，才勾选完成。
3. **本阶段交付物全部落地后**：`git add` 相关文件 → `commit` → `push origin main`。
4. **新需求/新 bug** 写入第 8 节「待纳入计划」，下一轮再排期。
5. **无法完成必须写卡点**（环境、硬件、依赖），禁止假装完成。

每阶段固定验收命令：

```bash
# 有 JDK + Android SDK 之后
./gradlew testDebugUnitTest
./gradlew assembleDebug
```

本阶段若环境未就绪，验收改为：文档齐全、目录正确、git 已推送。

## 3. 分阶段计划

### 阶段 0 — 仓库导入与计划文档

- **做什么**：解压、整理、写本计划与规格追踪任务列表。

- **测试**：`test -f app/build.gradle.kts && test ! -f JARVIS.zip`。
- **状态**：已完成（2026-10-30）。

### 阶段 1 — 构建基线可编译

- **做什么**：打通 JDK 17 + Android SDK 35 + Gradle，使工程能编译、能跑现有单测。
- **怎么做**：
  1. 安装 JDK 17，设置 `JAVA_HOME`。
  2. 安装 Android SDK `platforms;android-35`、`build-tools;35.0.0`，写 `local.properties`（不入 Git）。
  3. 核对 AGP / Gradle / Kotlin 版本是否互相兼容；不兼容则只改构建脚本到可编译组合。
  4. 跑 `testDebugUnitTest`，记录失败用例到 `docs/bug_report.md`。
- **交付**：构建成功日志摘要写入 `docs/test_report_stage1.md` 更新段。
- **完成标准**：`assembleDebug` 与 `testDebugUnitTest` 退出码 0。若镜像/SDK 不可达，在计划中写明卡点并停止本阶段，不伪造结果。
- **测试**：上述两条 Gradle 命令。
- **状态**：已完成（2026-10-31）。`testDebugUnitTest` 15 类 77 用例全绿；`assembleDebug` 产出 `app/build/outputs/apk/debug/app-debug.apk`（218,738,213 B）。Gradle 8.5 wrapper 升级为 8.11.1 以匹配 AGP；沙箱内存限制下 `org.gradle.jvmargs=-Xmx1536m`。

### 阶段 2 — 人格、对话、模型调度（分区 1–2）

- **做什么**：主界面三区布局、JARVIS 人格注入、多轮对话、模型优先级调度真实可用。
- **怎么做**：对照规格书 3.1 与功能 #1–#18、#2.1 模型策略；修 ChatEngine / ModelScheduler / Personality；模型选择与语音聊天接入导航。
- **交付**：可编译的对话链路 + 相关单测。
- **完成标准**：
  - 默认人格为 JARVIS 中文灵魂描述。
  - 文本发送后有流式回复路径（无模型时明确错误，不假回复）。
  - 用户模型 > LiteRT > API > 服务器 的调度可单测。
- **测试**：`PersonalityTest`、`ChatMessageTest`、对话集成测试。
- **状态**：已完成（2026-10-31）。`ModelScheduler.resolveOrLoad()` 按用户 > LiteRT > API > 服务器回退；全部不可用时 `ChatEngine` 返回 `NO_MODEL_MESSAGE`。导航已接通模型选择与语音聊天。`PersonalityTest`、`ChatMessageTest`、`ConversationPipelineIntegrationTest`、`ModelSchedulerTest` 及全量 `testDebugUnitTest` 通过。

### 阶段 3 — 唤醒、保活、默认助手（分区 3）

- **做什么**：8 种唤醒统一分发 + 前台保活 + VoiceInteractionService。
- **怎么做**：WakeEngine 各 Detector 必须有真实监听或「权限未授予」提示；禁止 `simulateDetection()` 冒充完成。
- **交付**：唤醒模块 + `KeepAliveServiceOrderingTest` / `WakeWordPipelineIntegrationTest` 通过。
- **完成标准**：代码路径完整；缺麦克风时提示；关机唤醒若不可实现，文档标明不支持。
- **测试**：唤醒相关单元/集成测试。
- **状态**：已完成（2026-10-31）。缺麦克风/加速度传感器时 `WakeEngine.unavailableReasons` 给出中文提示，聊天页展示，其他唤醒源继续可用。`JarvisVoiceInteractionSession` 通知 `HomeLongPressDetector`。`KeepAliveServiceOrderingTest`、`WakeWordPipelineIntegrationTest` 及全量 `testDebugUnitTest` 通过。关机唤醒仍不支持。

### 阶段 4 — 虚拟机（分区 4 + REQ-01/02/03/06/07/08）

- **做什么**：Haven 风格 PRoot 多发行版：创建/启停/终端/文件/软件包/镜像导入。
- **怎么做**：
  1. `ProotManager` 下载与设备 ABI 匹配的二进制（禁止 x86_64 包在 ARM 上假装成功）。
  2. `VmDistroManager` 真实 HTTP 下载 + SHA-256；失败明确报错。
  3. `VmTerminal` 只走 `ProotManager.executeCommand`。
  4. Root 凭据加密存储；危险操作二次确认。
  5. 未安装 PRoot/rootfs 时 UI 提示缺失组件，不返回假 shell。
- **交付**：VM 模块源码 + `VmManagerTest` + `VmSubsystemIntegrationTest`。
- **完成标准**：无 rootfs 时创建失败且有中文原因；有 rootfs 时命令 exitCode 来自真实进程。
- **测试**：VM 单测与集成测试。
- **状态**：已完成（2026-11-01）。`ProotManager` 仅接受 arm64-v8a；缺失二进制返回「PRoot 未安装」且 exitCode=-1。`VmManagerTest`、`ProotManagerTest`、`VmSubsystemIntegrationTest` 通过。

### 阶段 5 — 系统控制（分区 5，功能 #49–#68）

- **做什么**：电话、短信、日程、提醒、导航、媒体、设置、跨应用。
- **怎么做**：所有 Intent/Provider 调用前走 `PermissionManager`；无权限时请求或提示。`ReminderReceiver` 到期必须发通知。
- **交付**：系统控制页可用 + 权限检查测试。
- **完成标准**：无权限时不崩溃、不假成功；有权限时发出真实系统 Intent。
- **测试**：`PermissionControllerTest` 及新增控制器单测。
- **状态**：已完成（2026-11-01）。电话/短信/日历/WiFi/蓝牙/亮度走 `PermissionGate`；提醒经 AlarmManager + `ReminderReceiver`。`PermissionControllerTest` 覆盖无权限失败关闭。

### 阶段 6 — 智能家居（分区 6，#72–#87）

- **做什么**：统一设备抽象 + 至少一条真实传输（HTTP/局域网发现）；无设备时「未检测到设备」。
- **怎么做**：`DeviceTransport` 真实请求；内存 StateFlow 只作缓存。
- **交付**：智能中枢家居面板 + `SmartHomeAdapterTest`。
- **完成标准**：扫描无设备返回空列表 + 提示；控制失败返回错误字符串。
- **测试**：智能家居单测 + SmartHub 集成测试。
- **状态**：已完成（2026-11-01）。空扫描返回「未配置网关」或「未检测到设备」；`DeviceTransportTest`、`SmartHomeAdapterTest`、`SmartHubSubsystemIntegrationTest` 通过。

### 阶段 7 — 感知（分区 7，#101–#113）

- **做什么**：传感器姿态、ML Kit 检测、威胁规则；相机未授权时明确提示。
- **怎么做**：禁止硬编码场景名冒充识别成功。
- **交付**：感知管理器 + `ObjectDetectorTest`。
- **完成标准**：无相机权限时 API 返回失败原因；有传感器时姿态数据来自 SensorManager。
- **测试**：感知单测。
- **状态**：已完成（2026-11-01）。无相机权限返回「无相机权限，无法进行目标检测」；`ObjectDetectorTest` 通过。

### 阶段 8 — 健康（分区 8，#59–#71）

- **做什么**：PPG/蓝牙数据接入；无硬件抛明确错误；用药提醒走 AlarmManager。
- **怎么做**：禁止 `return 72` 一类假生命体征。医疗诊断保持规格允许的受限/预留。
- **交付**：健康模块 + `HealthModulesTest`。
- **完成标准**：无传感器时测量失败可测试；提醒可注册。
- **测试**：健康单测。
- **状态**：已完成（2026-11-01）。无心率硬件提示「设备无心率传感器」；用药提醒注册 AlarmManager。`HealthModulesTest` 通过。

### 阶段 9 — 安全（分区 9，#34–#48）

- **做什么**：生物识别、权限分级、设备管理员锁定/擦除、入侵检测。
- **怎么做**：DeviceAdmin 必须在 Manifest + `device_admin.xml`；未激活时锁定失败并引导激活。
- **交付**：安全中心页 + 安全单测。
- **完成标准**：未激活管理员时 wipe/lock 失败；加密走 `CryptoManager`。
- **测试**：安全相关测试。
- **状态**：已完成（2026-11-01）。Manifest + `device_admin.xml` 已声明；未激活 lock/wipe 返回失败并引导激活。加密走 `CryptoManager`。

### 阶段 10 — 自主决策与插件（分区 10，#117–#144，REQ-11/12/13）

- **做什么**：任务调度、主动建议、应急协议真实动作（拨号/短信/锁定需权限）、记忆导入导出、模型能力调度、插件加载。
- **怎么做**：应急 5 个分支必须调系统 API 或明确缺权限；云同步 URL 为空则禁用。
- **交付**：自主模块 + `AutonomousModulesTest` + 对话管线集成测试。
- **完成标准**：记忆 JSON 可导出再导入；调度 `registerDefaultProfiles()` 在启动时调用。
- **测试**：自主与集成测试。
- **状态**：已完成（2026-11-01）。启动注册默认能力画像；记忆 JSON 可导入导出；应急缺权限返回中文原因。`AutonomousModulesTest` 通过。

### 阶段 11 — 设置 10 标签 + 自定义层（分区 11）

- **做什么**：规格 3.3 的 10 个标签全部有真实绑定，外加智能中枢/安全/系统操控入口。
- **怎么做**：每个开关/列表绑定对应 Manager 的 StateFlow，禁止硬编码假日志/假声线。
- **交付**：Settings 各 Tab。
- **完成标准**：对照规格书 3.3 逐标签可点、可改、可持久化。
- **测试**：相关 UI 逻辑的 JVM 测试（能测的测）；其余列入实机清单。
- **状态**：已完成（2026-11-01）。十标签加智能中枢/安全/系统操控绑定真实 Manager；日志导出、声线库、背景图/主题色走真实路径。
