# JARVIS 项目参考说明

## 参考项目

### 1. Kai 9000（UI 和结构参考）

**项目地址**: https://github.com/SimonSchubert/Kai

**参考内容**:

#### UI 设计
- 简洁的卡片式消息气泡
- 底部导航栏设计
- 清晰的用户/AI 消息区分
- 现代化的 Material Design 风格

#### 项目结构
- 模块化设计（inference、data、ui、tools、mcp、skills 等）
- Repository 模式封装数据访问
- MVI/MVVM 架构模式
- 依赖注入（Koin）

#### 核心功能实现方式
- 对话引擎：MVI + Agent Loop 模式
- 模型调度：多服务 Fallback 架构
- 工具系统：可扩展的工具执行框架
- 记忆系统：跨对话持久化记忆

### 2. Haven（虚拟机参考）

**项目地址**: https://github.com/GlassOnTin/Haven

**参考内容**:

#### 虚拟机实现
- 基于 PRoot 的用户态 chroot（无需 root 权限）
- 多发行版支持（Alpine、Debian、Arch、Void）
- 每个发行版独立的 rootfs

#### PRoot 集成
- 下载和管理 PRoot 二进制文件
- rootfs 下载和解压
- 文件系统绑定（/dev、/proc、/sys 等）
- 环境变量配置

#### 桌面环境
- Wayland 合成器（labwc/wlroots）
- GPU 加速显示
- VNC/RDP 远程桌面

#### 文件管理
- 统一文件浏览器
- 跨文件系统操作
- rclone 云存储集成

#### 软件包管理
- 各发行版原生包管理器（apk、apt、pacman、xbps）
- 在 PRoot 环境内执行包管理命令

#### 终端实现
- SSH + Mosh + Eternal Terminal
- tmux 感知会话恢复
- 可配置键盘工具栏

## 模型接入说明

JARVIS 按规格书同时支持本地模型、外接 API 和个人服务器三种模型来源，由 `ModelScheduler` 统一调度，优先级为用户自有模型 > LiteRT/导入本地模型 > 外接 API 模型 > 个人服务器模型；当前模型加载失败时按此顺序回退，全部不可用时返回 `NO_MODEL_MESSAGE`。

### 外接 API 模型
- 实现：`model/ApiModel.kt`，调用 OpenAI 兼容的 `POST {baseUrl}/chat/completions`，支持非流式与 SSE 流式（`data:` 分片、`[DONE]` 结束）；HTTP 错误与空回答会显式失败，不伪造回答。
- 入口：设置 → 服务 → “OpenAI 兼容 API 配置”，可填写 API Key、基础地址和模型名称；三项需同时填写，清空三项即禁用。
- 持久化：配置写入 `jarvis_service` SharedPreferences，启动时由 `di/AppModule.kt` 恢复为 `configured_api` 模型。

### 个人服务器模型
- 实现：`model/ServerModel.kt`，直连用户服务器 `POST {serverUrl}/generate`，请求 `{prompt, system}`，响应 `{"response":"回答"}`；地址必须是完整的 HTTP(S) URL。
- 入口：设置 → 服务 → “个人服务器模型配置”。
- 持久化：同样写入 `jarvis_service`，启动时恢复为 `configured_server` 模型。

### 验证边界
- `ApiModelTest`、`ServerModelTest`、`ModelSchedulerTest` 以 Mock/本地端点验证协议解析、失败分支与优先级回退，**不构成**对真实第三方 API 或用户服务器的连通性验收。
- API Key 当前保存在应用私有 SharedPreferences 中，未做额外加密；真实网络调用、额度消耗与延迟均为 NOT_RUN。
- 模型列表见模型选择页的“API 模型”和“服务器模型”分组，可与本地模型自由切换。

## 虚拟机类型说明

> 以下是当前 JARVIS 实现边界，不把参考项目的 Wayland/GPU 能力写成已经落地的能力。

### 终端式 PRoot 环境
- 基于 PRoot 的用户态 Linux rootfs，不是 Hypervisor/QEMU 虚拟机。
- 提供终端命令、文件与部分软件包操作入口。
- 实例 rootfs 隔离和生命周期状态机已有 JVM 覆盖；arm64 真机与长运行会话未验收。

### 桌面式 PRoot 环境（部分实现）
- 当前桌面链为 Xvfb + XFCE + x11vnc + VNC，不是 Haven 的 Wayland/GPU 实现。
- VNC 协议解析、异常帧和状态流有 JVM/本地端点测试。
- 真机显示、输入、性能、兼容性及远程桌面体验仍为 NOT_RUN/BLOCKED。
