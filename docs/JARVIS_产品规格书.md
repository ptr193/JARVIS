# JARVS 产品规格书

> 从零重构的手机端智能 AI 助手，人格为《钢铁侠》JARVIS（中文版）。Kai 9000 项目**仅供参考**，不使用其任何源码。

---

## 一、项目概述

| 项 | 内容 |
|----|------|
| 项目代号 | JARVIS |
| 版本 | 0.0.1 |
| 基础方式 | **从零重构**，Kai 仓库文件仅供参考，不复制/借用其源码 |
| 目标平台 | 第一版：Android；后续：Linux / Windows / iOS / Mac |
| 包名 | com.jarvis.pineapple |
| 最低 Android 版本 | Android 6（API level 23） |
| APK 大小 | 不限 |
| 定位 | 手机端智能 AI 助手（同类：YoYo、小爱、小艺、Siri），可设置为系统默认助手 |
| 人格 | 《钢铁侠》JARVIS，说中文，"灵魂"描述需详细到每一个细节 |
| 发布方式 | 不发布到应用商店，侧载安装 |
| 默认模型 | 本地模型（可联网也可离线），用户可选，不选则默认后续加入的新模型 |
| 外接模型 | 保留 AI API 接入功能，用户自行配置 API 后调用；同时支持连接个人服务器上的 AI 模型 |
| 仓库处理 | 项目正式开始前清空仓库（或将 Kai 所有文件打包为 zip 存放 main 分支供实时查看，项目完成后删除） |

## 二、核心设定（已确认）

### 2.1 AI 模型策略

| 项 | 设定 |
|----|------|
| 默认模型 | 用户自有本地模型，优先级最高，不选则默认此模型 |
| 本地备选 | 原有 5 个 LiteRT 模型（Gemma 4 E2B 2.5B、Gemma 4 12B、LFM2.5 1.7B、Qwen3 0.6B 等），用户可手动切换 |
| 外接 API | 保留，用户自行配置 API Key 后调用对应模型 |
| 个人服务器 | 支持连接用户个人服务器上的 AI 模型 |
| 推理框架 | LiteRT-LM（预留抽象层以便后续更换） |
| 模型体积 / 分发 | 由用户自行处理 |

### 2.2 唤醒机制（全部实现）

| 唤醒方式 | 实现依赖 |
|---------|---------|
| 语音唤醒（唤醒词） | 常驻麦克风监听 + 唤醒词检测 |
| 电源键连按 | AccessibilityService |
| 通知栏按钮 | Notification action |
| 通知点击 | PendingIntent |
| 摇一摇 | 加速度传感器 |
| 蓝牙设备按键 | BluetoothHeadset / MediaSession |
| 快捷设置磁贴 | TileService |
| 应用图标双击 | App Shortcut |
| **关机后语音唤醒** | 可实现则实现（关机时仅保留语音监听，唤醒后立刻开机）；无法实现则忽略 |

### 2.3 后台与保活

| 项 | 设定 |
|----|------|
| 沉睡模式 | 浅睡：进程常驻、服务存活、不占 CPU |
| 保活手段 | 前台服务常驻通知 + 电池优化白名单引导 + 自启动权限引导 |
| 默认助手角色 | 抢占系统"默认数字助手"，长按 Home 唤起 |
| 辅助功能服务 | 开启 |
| 麦克风 | 始终监听语音唤醒 |

### 2.4 语音

| 项 | 设定 |
|----|------|
| 语音库 | 本地语音库 |
| 默认声线 | 《钢铁侠》中文版 JARVIS 声线 |
| 其他声线 | 用户如需使用其他声线，需自行准备 |
| 语言 | 支持现有通用的一百多种语言 |

## 三、界面设计

### 3.1 主界面

```
┌─────────────────────────────────────┐
│  [虚拟机]    声音播放按钮    [设置]  │  ← 顶部
│                                     │
│                                     │
│        对话内容区域                  │
│                                     │
│                                     │
│  [模型选择] 默认：本地模型           │
│  [📎上传] [输入框............] [发送]│  ← 底部
└─────────────────────────────────────┘
```

- 顶部：左侧"虚拟机"入口，中间声音播放按钮（扬声器图标），右侧"设置"入口
- 中部：对话内容
- 底部：模型选择按钮（默认本地模型）、上传文件/图片、输入框、发送按钮

### 3.2 虚拟机界面

```
┌─────────────────────────────────────┐
│  虚拟机名称            [功能按钮]    │  ← 顶部（功能按钮按下展开新界面，再按退出）
│                                     │
│  [软件包] [可下载发行版] [已下载] [文件管理] │  ← 4 个标签
│                                     │
│        对应标签内容区                │
│                                     │
│  [导入系统镜像文件]                  │  ← 底部
│  [输入框............] [发送/回车]    │
└─────────────────────────────────────┘
```

四个功能标签：
1. **软件包**：包管理操作
2. **可下载的 Linux 发行版**：连接官网自动下载
3. **已下载的 Linux 发行版**：管理已下载镜像
4. **当前虚拟机的文件管理**：文件浏览

底部支持导入系统镜像文件。

### 3.3 设置界面（可滑动，10 个标签页）

| 标签 | 名称 | 功能说明 |
|------|------|---------|
| ① | 代理 | 设置"灵魂"的界面（人格描述），同 Kai |
| ② | 服务 | AI、API 接入界面，以及服务器连接 |
| ③ | 工具 | 技能导入界面 |
| ④ | 虚拟机设置 | 虚拟机相关配置 |
| ⑤ | 状态 | 设备当前运行信息（CPU、GPU、内存、温度等） |
| ⑥ | 仓库 | 用户提供的仓库（GitHub、GitLab 等） |
| ⑦ | 连接设备 | 已连接的可控设备 + 可连接未连接的设备（手机、电脑、家居） |
| ⑧ | 语言语音 | 设置 AI 声线和语音，声线自备，100+ 语言 |
| ⑨ | 日志 | 各种日志展示，以文件管理形式展示 |
| ⑩ | 通用 | 通用设置（背景图设置、图标自定义、唤醒方式） |

## 四、新增功能（相对 Kai）

### 4.1 本地模型选择
- 本地提供 5 个原有 LiteRT 模型 + 用户自有模型，共 6 个可选
- 用户可自行选择默认本地模型
- 不选择则默认为用户自有模型（优先级最高）

### 4.2 Linux 环境拓展（多虚拟机）
- 支持选择 Linux 发行版，自动连接官网下载
- 支持用户自行提供镜像文件
- 支持配置**多个独立虚拟机环境**
- 提供 **GUI 界面**访问和展示能力
- 虚拟机互相不干扰，同时运行个数由设备性能决定
- 虚拟机之间存在连接，每个根目录用户可查看
- 用户可通过图标打开软件，自行操作虚拟机

### 4.3 界面自定义
- 自定义软件界面风格
- 自定义背景图
- 自定义软件图标和颜色
- 支持第三方输入法（百度输入法、搜狗输入法等）

### 4.4 智能家居与设备连接
- 可连接智能家居
- 可连接所有 AI 助手可操作的设备

### 4.5 架构演进
- 当前版本所有功能在本地运行
- 后续版本将功能移入服务器以释放手机性能

## 六、技术架构

### 6.1 基础架构（从零构建，参考 Kai 设计）

| 维度 | 技术选型 |
|------|---------|
| 语言 | Kotlin |
| UI | Jetpack Compose (Material 3) |
| 构建 | Gradle (Kotlin DSL) |
| 依赖注入 | Koin |
| 网络 | Ktor |
| 持久化 | SQLDelight + EncryptedSharedPreferences |
| 加密 | BouncyCastle (AES-256-GCM) |
| 端侧推理 | LiteRT-LM |
| 沙箱 | proot (多虚拟机) |

| 核心引擎 | 对话管理、记忆系统、工具调用调度 |

| 保活服务 | 前台服务 + 保活引导 |
| 默认助手接入 | AssistantRole + VoiceInteractionService |
| 人格系统 | JARVIS 中文人格 prompt + 情绪适配 |
| 模型管理层 | 本地模型 / API 模型 / 服务器模型统一调度 |

## 七、开发与交付流程

### 7.1 开发原则

1. **分区分任务**：项目分成多个大分区，大分区划为多个小任务
2. **每个小任务明确**：做什么、实现什么、交付什么
3. **每分区测试**：完成一个大分区后直接运行程序测试（不打包），出问题立刻规划修复
4. **逐区推进**：测试不报错再继续下一个分区
5. **全量测试**：所有分区完成后运行测试，不报错再打 Debug APK 实机测试
6. **修复后发布**：修复所有 Bug 后打包发行版 APK

### 7.2 汇报机制

- 每完成一个阶段，向用户汇报当前状态
- 明确无需修改再继续下一步
- **每次交付一并告知当前进度百分比**
- 做到 UI 界面时，提供预览界面给用户检查，确认无误再继续
