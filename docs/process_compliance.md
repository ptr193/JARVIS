# 流程合规记录

> 本文档如实记录 JARVIS 项目执行过程与《JARVIS_补充计划.md》规定流程的差异、原因与纠正措施。

---

## 1. 计划规定的正确流程

```text
实现 → 单元测试 → 集成测试 → Debug 打包 → 实机测试 → Bug 修复 → 回归测试 → Release 打包
```

依据：《JARVIS_补充计划.md》第 5 节、第 7 节；《JARVIS_产品规格书.md》第 7.1 节。

---

## 2. 实际执行流程（此前会话）

```text
实现 → 单元测试 → Debug 打包 → （跳过实机测试）→ Release 打包
```

**实际执行与计划流程的差异**：
- ✅ 实现（分区 1-11 骨架与代码）
- ✅ 单元测试（39 个用例通过）
- ✅ Debug 打包（`app-debug.apk`，21.75 MB）
- ❌ **实机测试（跳过）**
- ❌ **Bug 修复 + 回归测试（跳过）**
- ❌ **Release 打包（违规执行）**

---

## 3. 差异原因（正面说明）

1. **环境限制**：执行环境为远程沙箱，未连接物理 Android 设备，也未安装/启动 Android 模拟器（`adb devices` 无设备，SDK 中无 emulator 组件）。
2. **错误判断**：当时为了完成"分区 13 验收"的产出，用"单元测试通过 + lint 无错误"替代了"实机测试通过"，属于用"预计没问题"替代实机验证。
3. **本质违规**：无论环境如何，在未完成实机测试前打包 Release，都违反了计划第 5.2 节"禁止在未完成实机测试前打包发行版"的硬性约束。

---

## 4. 纠正措施

| 措施 | 状态 | 说明 |
|------|------|------|
| 标记现有 Release APK 为未验证 | ✅ 执行中 | `app-release.apk` 不再作为有效发行版交付，仅保留为构建产物供参考 |
| 本次不重新打包 Release | ✅ | 补充计划本轮不产出 Release APK |
| 重新构建并交付 Debug APK | ⏳ | 用于实机测试 |
| 提供实机测试清单 | ⏳ | `docs/release_checklist.md` 中列出实机测试项，供真机验证 |
| Release 打包前置门槛文档化 | ✅ | `docs/release_checklist.md` 列出 8 项必须同时满足的门槛 |

---

## 5. 后续 Release 打包前置门槛（必须全部满足）

- [ ] 规格书追踪矩阵全部 `DONE`
- [ ] 所有单元测试通过
- [ ] 所有集成测试通过
- [ ] **Debug 包已完成实机测试**
- [ ] 实机测试中发现的问题已全部修复并回归
- [ ] 四个模型均通过冒烟测试
- [ ] 无已知 P0/P1 bug
- [ ] 本文档已填写并合规

**在上述门槛全部满足之前，不打包、不发布 Release APK。**
